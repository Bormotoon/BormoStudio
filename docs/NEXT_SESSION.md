Запуск: `run … --skip program program_subtitles reels reel_render`.

- **Синк и экспорт готовы:** `_studio/export/Studio.fcpxml` и `Studio.xml`.
  К проверке: `DJI_0689` (40 % окон > 20 мс) и `ведущий 2/C0002` (7,7 с,
  измерить нечего).
- **Падение 19→20 октября:** через сутки прогона стадия speakers (микрофоны)
  держала в памяти все 30 файлов рекордера и раздувала подписи голоса; oomd
  убил прогон и VS Code. Исправлено (`43eefa6`), результат тот же.
- **Микрофонный метод на этом рекордере бесполезен:** копии одного Zoom
  считаются разными микрофонами, 136 мин ушло в `overlap`. Сделан каскад
  (`speakers.method: cascade`): pyannote на каждом источнике → Light-ASD на
  крупных планах → Gemma, каждый шаг только для неуверенных фраз; уверенность —
  апостериорная вероятность с надёжностью каждого источника, измеренной по
  данным (Dawid–Skene, контрольные фразы). В `settings.yaml` furry добавлены
  `speakers` (cascade, cuda) и `llm` (managed gemma4, порт 11440); копия
  прежних настроек — `/srv/storage/files/.uvf-tmp/furry-settings-2026-10-20.yaml`.
- **Что узнали:** в разговоре двое (≈108 и ≈35 мин речи); «ведущий 2» и
  «гость 2» — вторые ракурсы тех же людей. Сырые эмбеддинги pyannote у разных
  людей дают косинус 0,95–0,99 — сравнивать надо центрированными (один человек:
  медиана 0,79, разные — до 0,40). Надёжность источников: «гость» 0,92–0,95,
  «ведущий» 0,89, «ведущий 2» 0,88, рекордер 0,78–0,83, DJI 0,77, «гость 2»
  0,66, NSFW 0,53. Один звук с весами надёжности решает 82–85 % речи (с равными
  весами было 44 %).
- **Сейчас в проекте результат cascade-v2** (уверенно 86,7 % речи): видео
  получило надёжность 0,5, Gemma без подсказок по звуку — 54 % на контрольных.
  Причины найдены и исправлены в cascade-v3 (`60f83bc`): «люди» — только с ≥ 3 %
  речи (обрывок на 2,5 мин был привязан к камере «гость 2» и сбивал Gemma),
  молчащее лицо голосует за остальных по их доле речи.
